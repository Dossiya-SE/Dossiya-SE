## 1. Scientific purpose

The figure must show the mathematical dependency/role architecture used or explicitly specified across the public profile. It is not a mastery map, score, ranking, credential, or exhaustive map of mathematics.

The mathematical object is a typed directed multigraph

```math
\mathcal G_M=(V_M,E_M,\tau_V,\tau_E),
```

where `V_M` is the set of mathematical-domain nodes, `E_M` is the set of declared relations, `tau_V` assigns node classes, and `tau_E` assigns relation types.

Only the following relation types are permitted:

```text

```

Every visible edge must resolve to one record in the frozen graph JSON. Decorative edges are prohibited.

## 4. Visual encoding

Node position may be generated by a deterministic graph-layout algorithm, but position is not evidence of importance or mastery.

Recommended layer structure:

```text
Foundations
→ Structures / Geometry
→ Dynamics / Computation
→ Inference / Uncertainty
→ Decision / Viability
```

Relation type must be encoded by line style/marker in addition to color. Node class must be encoded by shape/label family in addition to color.

## 5. Mathematical-art rule

The visual geometry must be generated from the graph data. A renderer may choose coordinates, spacing, label placement, and edge routing, but it may not add/remove/retype graph relations without changing the canonical graph data.

Deterministic pipeline:

```text
mathematics_universe_graph_v1.json
→ schema/ID validation
→ typed graph G_M
→ deterministic layout with fixed seed/config
→ collision resolution
→ semantic SVG layers
→ adaptive theme tokens
→ raster/PDF/PPTX derivatives
```
