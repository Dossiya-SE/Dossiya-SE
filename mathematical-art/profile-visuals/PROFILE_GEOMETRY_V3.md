# PROFILE-GEOMETRY-V3

This is the governing geometry system for the GitHub profile visuals.

## Core rule

A geometric primitive may appear only when it has a defensible role:

- **point** — state, node, source or location in an abstract space;
- **line / segment** — relation, transition, trajectory or affine one-dimensional structure;
- **plane / affine 2-flat** — infrastructure layer or model space;
- **regular polygon** — typed node or ordered navigation marker;
- **ellipse** — bounded continuous state/domain region;
- **hyperplane** — explicit constraint or critical boundary;
- **orthogonal projection** — geometric distance to a labeled hyperplane.

A polygon is never called an affine flat. A projected parallelogram may depict an affine plane, but the finite quadrilateral is only its visual window.

## Technology responsibilities

**TikZ/Overleaf** is the publication-quality geometric composition reference.  
**Julia** carries the numerical affine geometry.  
**Python** is the authoritative GitHub SVG renderer because GitHub README SVG must be deterministic and script-free.  
**React + CSS** provides the interactive mirror for the web portfolio.  
**Go** provides lightweight static vector export.  
**C#** exposes the same primitives for engineering/CAD integration.

The languages are complementary. They are not duplicated merely to display a technology list.


## Release gate

Every public README visual is regenerated from the governed geometry contract and raster-tested at **980 px** and **640 px**. Human visual QA additionally checks for text collision, clipping, non-portable SVG math glyphs, shape ambiguity, and misleading geometric implication.

The public README does not display the standalone flat-shape catalog. Plane figures and affine-flat mathematics remain internal design primitives used to construct the existing research visuals.
